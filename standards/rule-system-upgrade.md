# 规则系统升级草案

## 目标

把当前以页面结构校验为主的规则体系，升级为一套可复用、可声明、可机检、可审计的多层规则系统。

本次升级优先解决以下问题：

- Web 后台、App、小程序之间页面骨架和组件样式不一致
- 模块图标、状态标签、按钮风格和局部 CSS 写法漂移
- 需求文档抽屉的行文风格、完整度、逻辑结构不统一
- 规范主要停留在文字描述，缺少脚本化检查

## 规则分层

### 1. 设计基线层

文件：`standards/design-tokens.json`

负责跨平台统一的视觉语义：

- 颜色、字体、间距、圆角、阴影、边框
- 状态色与状态文案映射
- 图标尺寸、按钮高度、抽屉宽度
- 组件的推荐 class token

### 2. 端规范层

文件：`standards/platform-rules.json`

负责 `web`、`app`、`miniapp` 的页面骨架和交互习惯：

- 平台入口页
- 列表页
- 详情页
- 表单页
- 弹窗/抽屉
- 空状态/错误态/底部安全区

### 3. 文档规范层

文件：`standards/doc-spec.json`

负责需求文档抽屉的内容结构、写作风格和完整度：

- 统一标题结构
- 必填章节
- 推荐行文方式
- 状态、限制条件、异常边界等必备信息

### 4. 模块声明层

文件：`standards/module-spec.json`

负责模块元数据的统一声明格式：

- 模块名称、平台、图标、文档入口
- 页面类型、状态集合、是否需要文档抽屉
- 模块允许复用的公共组件

### 5. 机检与审计层

现有：

- `scripts/lint-ui.js`
- `scripts/audit-ui.js`

新增：

- `scripts/audit-docs.js`

后续可继续补：

- 图标白名单检查
- 状态文案一致性检查
- class 命名和组件接入检查

补充规则文件：

- `standards/ui-consistency-rules.json`
  负责图标来源、状态标签、CSS 共享约束、需求文档抽屉入口与内容风格的一致性定义

## 实施策略

### Phase 1：补规则骨架

- 建立分层标准文件
- 提供文档模板
- 建立审计脚本入口

### Phase 2：锁定新增产出

- 新页面脚手架接入新规则
- 新文档按统一模板填写
- 审计命令进入日常工作流

### Phase 3：治理存量页面

- 先公共组件
- 再高频业务页
- 最后按平台分批收敛旧模块

## 迁移原则

- 不一次性推倒现有页面
- 先补标准，再补脚本，再收敛存量
- 可机检的规则优先进入脚本
- 无法稳定机检的内容先进入模板与人工审查清单
- 如需临时跳过某份文档审计，应使用显式跳过标记，而不是把模块路径长期写入排除名单
