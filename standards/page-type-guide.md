# 页面类型判定指南

## 目的

统一判断页面属于哪一类模板，减少“该不该带导航”“要不要接平台框架”“是否只是索引页”的误判。

本指南对应以下类型：

- `portal-index`
- `platform-entry`
- `iteration-index`
- `module-page`

## 一句话判断法

### `portal-index`

如果页面是“全局总入口”，只负责展示平台卡片或总览入口，不负责具体业务承载，就是 `portal-index`。

典型特征：

- 位于平台或仓库总入口位置
- 不使用左侧 `system-nav`
- 只做总览和跳转

典型示例：

- 根目录总导航页
- 平台总览型入口页

### `platform-entry`

如果页面是“某个平台下所有模块的导航入口”，需要展示模块列表和平台级导航，就是 `platform-entry`。

典型特征：

- 页面本身不是业务详情
- 有平台级导航
- 用来进入某个平台下的多个模块

典型示例：

- `admin-portal/index.html`
- `field-app/index.html`
- `mini-program/index.html`

导航补充规则：

- 目录型 `index.html` 的左侧导航底部必须固定提供两行返回入口
- 第一行：返回所属平台/上级导航
- 第二行：返回总导航
- 两行都使用统一弱化链接样式，不得只保留其一
- `迭代索引/` 与 `零散设计/` 不套用这条双返回规则

### `iteration-index`

如果页面只是“按迭代周期组织入口”，展示某次迭代涉及了哪些页面或模块，而不直接承载业务开发，就是 `iteration-index`。

典型特征：

- 位于 `迭代索引/`
- 只做聚合展示和跳转
- 可以有导航，但不承载具体业务功能

典型示例：

- `迭代索引/index.html`
- `迭代索引/202603上.html`

### `module-page`

如果页面已经进入具体业务模块，承载列表、详情、表单、弹窗、业务说明或具体交互，就是 `module-page`。

典型特征：

- 已经在某个模块内部
- 展示真实业务内容
- 不应包含平台级 `system-nav`

典型示例：

- 模块首页
- 列表页
- 详情页
- 模块内部子页面

## 易误判场景

### 场景 1：模块首页

即使文件名叫 `index.html`，只要它已经是某个模块内部的真实业务页，也仍然是 `module-page`，不是 `platform-entry`。

示例：

- `admin-portal/maintain-admin/index.html`
- `admin-portal/asset-admin/index.html`

### 场景 2：文档页

即使位于 `doc/` 下，只要它属于模块内部页面，也仍按 `module-page` 处理；但审计口径可以对业务文档页单独放宽，不代表类型变化。

### 场景 3：旧入口跳转页

如果页面只是一个重定向壳子，但位于模块内部，仍可暂时登记为 `module-page`，后续再根据实际用途决定是否保留。

## 导航判断

### 需要平台级导航

- `platform-entry`
- `iteration-index`

### 不使用平台级导航

- `portal-index`
- `module-page`

## 抽屉策略判断

### Web

- 默认手动打开
- 不应自动 `DocPanel.autoShow`

### App / 小程序

- 默认自动展示
- 可手动关闭

## 判定顺序

每次新页面先按下面顺序判断：

1. 它是不是总入口？
2. 它是不是某个平台的模块导航入口？
3. 它是不是某次迭代的聚合页？
4. 如果以上都不是，就按 `module-page` 处理。

## 开发路径判断

页面类型判断完成后，还要继续判断它属于哪种开发路径。

### 持续迭代页面

如果页面属于门店后台、运维后台、作业端 App、用户端 App、用户小程序、门店小程序等既有产品体系中的持续迭代页面，优先按“复刻最接近页面再改造”的方式处理。

典型特征：

- 已有线上页面或既有原型可参考
- 本次主要是新增字段、调整卡片、补新状态、加一个新模块入口
- 整体骨架不需要从 0 开始重构

### 0-1 独立模块

如果页面属于全新模块，且模块边界、信息架构、页面清单都需要重新定义，则按“0-1 独立模块”处理。

典型特征：

- 模块需要单独定义首页、子页面、文档结构
- 需要先梳理模块边界和页面关系
- 风险投诉、通信卡管理这类模块更接近这种路径

## 与脚手架的对应关系

- `portal-index` → 总览入口页
- `platform-entry` → 平台入口页（有导航）
- `iteration-index` → 迭代索引页（有导航，仅聚合）
- `module-page` → 模块业务页（无平台导航）
