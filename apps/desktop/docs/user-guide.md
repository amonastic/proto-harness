# Proto Harness Agent 用户手册

版本：0.1.1
适用：macOS 13+，Apple Silicon（arm64）
定位：本地优先的产品 Agent 客户端。业务规则、需求、裁决与交付保存在你自己的项目文件中。

## 1 安装

1. 打开 `Proto Harness Agent-0.1.1-arm64.dmg`。
2. 将 `Proto Harness Agent.app` 拖入 `Applications`。
3. 推出磁盘映像，从「应用程序」打开。

本地产物使用 ad-hoc 签名，**没有 Developer ID 签名，也没有公证**。如果系统提示无法验证开发者：

- 在 Finder 中右键点击应用，选择「打开」，再确认一次；或
- 在终端执行（仅当你信任该产物时）：

```bash
xattr -dr com.apple.quarantine "/Applications/Proto Harness Agent.app"
```

正式分发需要发布负责人提供 Apple Developer ID 与公证凭据；当前产物不应被描述为正式签名发行版。

## 2 首次使用

启动后进入「我的产品」。

默认项目目录：`~/Documents/Proto Harness Projects`。可以在「模型与工具设置」中修改；新建与接入的项目会放在这里。

默认分析来源是「本地规则分析」：只从你输入的目标、约束和来源文本中提取候选知识，不调用模型。它适合体验流程与重复验证，分析质量与模型模式不同。

### 配置模型（可选）

进入「模型与工具设置」：

- 运行时选择「OpenAI 兼容模型服务」；
- 填写服务地址（例如 `https://api.openai.com/v1`、团队网关或本机 Ollama 的 `/v1` 地址）；
- 填写模型 ID 与 API Key；
- 点击「测试连接」，成功后「保存设置」。

API Key 只保存在 macOS 系统安全存储（Keychain），不会写入项目文件、日志或导出包。模型调用会把当前任务选定的上下文发送到你配置的服务；客户端会在分析结果上标注来源。

### 外部工具

- Git：用于项目文件的提交与推送，需系统已安装 Git。
- pen.dev：首版仅做能力探测，**不执行 .pen 设计操作**；HTML 原型与静态交付不依赖 pen.dev。
- OpenCode：首版未接入。当前生产运行时适配器为 OpenAI 兼容 HTTP。

## 3 旅程一：新建产品

1. 在首页点击「新建产品」。
2. 填写产品名称、目标、服务对象、已有约束、端与角色。约束一行一条，越具体越好。
3. 可选：选择参考资料（Markdown、文本、JSON、HTML、CSS）。参考资料作为来源保存，不会自动成为事实。
4. 点击「开始分析」。
5. 在「确认基线」步骤：
   - 勾选要进入当前基线的候选规则；
   - 补充遗漏的规则；
   - 回答阻塞未知项；不确定时也要明确写「暂按现状处理」之类的业务判断；
   - 确认端与角色；
   - 点击「创建产品并建立基线」。
6. 在工作台点击「发起需求」，填写需求标题、目标与约束，点击「创建并分析」。
7. 如果出现业务冲突：
   - 阅读「现行规则」与「新需求口径」；
   - 选择「采用新口径 / 保留现行规则 / 附加条件后采用」；
   - 填写裁决理由；
   - 点击「确认并应用裁决」。
   新规则进入 **planned** 基线；当前基线不会自动切换。
8. 点击「生成需求与设计」，得到需求文档、交互规格、自包含 HTML 原型、CSS 规范与映射。
9. 在原型与 CSS 规范中核对；点击「评审通过」。
10. 点击「创建交付版本」。交付会固定需求版本、规则版本与产物清单，并导出静态站。

## 4 旅程二：接入已有项目

1. 在首页点击「接入已有项目」。
2. 选择已有项目目录；目录只读，导入不会修改原文件。
3. 点击「扫描目录」。支持 Markdown / 纯文本 / JSON / HTML / CSS；单文件 ≤ 2 MB，最多 4000 个文件。
4. 检查扫描结果：
   - 产品名称与目标；
   - 端与角色；
   - 同一主题的口径冲突：选择当前口径并填写裁决理由；
   - 其他候选知识：勾选要进入基线的内容。
5. 点击「创建项目与导入基线」。项目空间会创建在设置的项目目录，来源目录保持不变。
6. 在「业务大脑」中查看规则、来源、对象、能力、裁决与基线。历史口径会标记为「已替代」。
7. 按旅程一的 6–10 步完成一次基于已有能力的迭代与交付。

## 5 业务裁决与版本

三个维度分开记录：

- 判断状态：候选 / 已确认 / 已替代；
- 生效状态：计划生效 / 当前生效 / 已停用；
- 交付状态：草稿 / 已评审 / 已交付。

裁决绑定提案的内容哈希与需求基准版本。提案或基准变化后，旧裁决不能继续套用，界面会要求重新确认。

选择「保留现行规则」时，需求文档会保留原始输入与裁决记录，但后续原型与交付按现行规则生成，界面显示「未采纳」的原口径；不会继续实现被否决的方案。补答阻塞未知项后，提案会自动重绑到新的需求修订，再进入裁决，不要求重新分析。

「采用新口径」不会自动让规则上线。需要明确生效时，在「业务大脑 → 基线」中点击「明确生效」，填写生效依据。切换后：

- 新基线成为当前基线；
- 旧基线保留为已停用；
- 规则生效状态同步更新；
- 历史交付保持固定，不随当前规则漂移。

## 6 Git 同步

在「交付记录 → Git 同步」：

1. 未初始化时点击「初始化 Git 仓库」（只创建 .git 与 .gitignore）。
2. 选择要提交的项目文件，填写提交信息，点击「提交所选文件」。
3. 配置 origin 后，点击「推送到 origin」并确认。

只提交你选择的项目文件；`.runtime` 与 `node_modules` 不会进入提交。推送不使用强制参数。密钥不进入项目文件。两台 Mac 可通过同一 Git 仓库接续；模型与 Git 凭据需要各自配置。

交付创建时会把产物复制到交付目录的 `frozen/` 并记录哈希。之后修改需求或原型只会影响新交付；对历史交付重新导出仍使用冻结内容。

## 7 数据、备份与迁移

项目目录包含：

- `project.json`：产品、端与当前基线指针；
- `brain/`：证据、对象、能力、规则修订、基线、裁决；
- `requirements/`：需求任务、历史版本与产物；
- `design/`：设计 token 与导入来源的 CSS 声明；
- `deliveries/`：交付清单与静态导出；
- `.runtime/`：可重建索引与日志，已默认加入 `.gitignore`。

备份项目目录即可备份业务资产。`project.json` 中的绝对路径只代表当前设备；跨设备恢复时，外部来源可能需要重新选择。格式升级应保留原数据并提供迁移路径；当前版本为 `pha-project-v1`。

## 8 常见问题

**模型调用失败**

检查服务地址、模型 ID、Key 与网络；在设置中点击「测试连接」。失败时任务会保留为「已阻塞」，错误摘要写入 `.runtime/model-errors/`，不会把截断文本当完整需求。

**看不到冲突**

分析器只把有文本依据的规则差异呈现为冲突。如果材料没有写出「必须 / 不得 / 仅」等约束，请补充需求描述后重新分析。

**候选规则不是想要的**

新建产品时取消勾选；接入项目时在「其他候选知识」中取消勾选。候选知识不会自动成为已生效规则。

**Git 提交失败**

确认系统已安装 Git，并配置 `user.name` 与 `user.email`。没有远端时可先本地提交；推送需要 origin。应用不会修改 Git config。

**pen.dev 显示已安装但无法生成设计**

首版只做应用探测，不执行 pen 设计操作。HTML 原型、CSS 规范与静态交付仍可用；pen 相关步骤应在交付风险中标注未完成。

**应用无法打开**

当前是 ad-hoc 签名本地测试产物，不是公证发行版。使用右键「打开」或按第 1 节移除 quarantine。若仍失败，请在终端运行应用二进制查看错误，并保留项目目录。

## 9 安全边界

- 渲染层无 Node 权限；所有权威写入经主进程 IPC 进入业务内核。
- 预览 HTML 在隔离 iframe 中运行，不获得桌面文件系统、凭据或 Node 能力。
- 模型只能产生候选；规则、基线与交付由业务内核写入。
- 导出包会校验资源完整性，并拒绝疑似包含密钥的内容。
- 本项目开源；用户业务资料由用户自行控制，不随产品源码公开。
