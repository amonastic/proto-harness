# 业务知识沉淀（Business Knowledge Capture）

本 skill 回答一个问题：**本轮沟通里出现的业务判断，值不值得留下来？**

它只做判断与提示，不授权写入。AI 与用户沟通需求的过程中，业务逻辑往往以口头结论的形式出现（「一般来讲」「默认就是」「这种情况通常」），这些结论下次还会用到，但不会自动留在代码或页面里。本 skill 让 AI 在收口时主动提示用户：这部分是否要沉淀成一条业务知识。

## Trigger

命中以下任一情况时使用本 skill：

- 业务需求沟通已经闭环，形成稳定的业务对象、角色、端范围、权限、配置或状态流转口径。
- 需求页面、需求抽屉、需求文档或任务包已落地，其中含可复用业务规则，而不是一次性 UI 实现。
- 用户在对话中确认了业务规律（「默认就是 / 一般来讲 / 以后可以默认 / 这种情况通常」）。
- 用户纠正了 AI 对业务域、角色、流程、状态或配置影响的理解。
- 同类业务判断在多次需求、多个页面或多个文档中反复出现。

## 边界

- 本 skill **不自动写入**任何外部知识库，也不得在用户未确认前创建条目。
- 沉淀位置由使用方自己的配置声明，本 skill 不内置任何本机路径、产品名或知识库名。
- 判断材料不可读时，必须说明失败原因并把结论降级为「待确认」，不得声称已完成判断。
- 需求文档、页面正文与需求抽屉本身可以承载业务说明；本 skill 处理的是**跨需求复用**的业务知识，两者不互相替代。

## Required Checks

1. 读取使用方声明的业务知识库入口与抽取标准（位置见 `governance.config.json` 的 `businessBrain.root`，或 `BUSINESS_BRAIN_ROOT` 环境变量；未配置时向用户询问位置）。
2. 判断候选知识是否满足「可复用」：是否会在下一次需求、另一个页面或另一条流程中再次用到。
3. 剔除不属于业务知识的材料：
   - 纯 UI 风格、页面壳、视觉细节；
   - 一次性排版、临时口径；
   - 模型推断而非用户确认的结论；
   - AI 协作或工程经验（这类内容应走项目规则与 Harness 治理，不走业务知识沉淀）。
4. 输出判断，等待用户确认；用户确认后，才按使用方知识库自身的写入协议落条。

## Output

```text
业务外脑沉淀判断：
结论：建议沉淀 / 暂不沉淀 / 待确认
候选知识：
建议状态：candidate / confirmed / pending
依据：
适用范围：
不适用范围：
目标目录或候选文件：
不写入内容：
需要用户确认：
```

判断完成后必须显式询问用户是否沉淀；用户未确认时，本轮不产生任何写入动作。

## 与项目规则的关系

- 项目内规则写入（`AGENTS.md`、`harness/*`、`standards/*`、skills）走 `harness/04-规则准入与治理.md` 的准入与 ROI 评分，不触发本 skill 的沉淀流程。
- 本 skill 只处理「业务知识」这一类外部沉淀；规则的沉淀与治理另有其流程，两者不得混用。
