# Harness 规则目录导航

本目录集中收纳设计稿治理项目中面向 AI 协作与执行的 Harness 规则、Prompt 模板和规则审阅材料。

`harness/` 是项目根目录下的 AI 协作规则资产，不属于 `doc/平台治理/`。平台治理文档可以引用本目录，但不得把 Harness 视为平台治理子目录或平台文档的附属材料。

## 最小读取链

1. 根目录 `AGENTS.md`：唯一主入口，负责最高优先级规则、执行状态、开工闸门、交付边界和高风险红线。
2. `00-执行总入口.md`：Harness 最小入口，负责用途、状态判断、握手和 MCP 偏好。
3. `01-强制闸门.md`：每轮执行前后的通用闸门、依据、开工声明、最终回复和禁止事项。
4. 按任务类型继续读取下方分卷。

## 工具适配层

`.codex/skills/*`、`.claude/skills/*`、`.agents/skills/*`、`.codebuddy/skills/*` 和 `.codebuddy/rules/*` 属于工具适配层。它们只做不同 AI 工具的入口适配或技能包装，不作为新的母本规则；本目录整理不移动、不改名、不改内容。

## 维护规则

- 新增 AI 执行规则时，先判断应进入 `AGENTS.md`、本目录、`DEVELOPMENT.md`、`standards/*` 还是工具适配层。
- 能放入既有主入口或专项规则的，不新增平行规则文件。
- 规则审阅、缺陷清单、迁移方案等过程材料进入 `archive/`，避免误认为执行必读规则。
- 业务知识、端范围、权限和配置判断继续进入 Obsidian 业务外脑，不写入项目 Harness。

## 已沉淀的跨模型专项审阅模板

- 「历史快照与迭代引用安全审阅」模板正文已外置 `harness/rules/历史快照安全审阅.md`；所在分卷原位保留触发钩子行。
- 该模板来源于一次对原项目的快照污染专项审阅提炼，目的是让所有执行本项目的大模型在涉及 `迭代索引/`、`snapshots/`、历史引用和 `docs.js` / `doc-panel.js` 时都按同一检查框架审阅。
- 该模板是审阅与风险识别模板，不是授权改动模板；发现风险后仍需按 `AGENTS.md` 判断是否进入文件执行态。
