# 执行总入口

本文件是 Harness 分卷后的最小入口，负责告诉 AI 当前任务如何进入规则体系；具体闸门、契约、纠偏、执行、验证按 README 路由继续读取。

## 用途

本文件把仓库当前规则、项目资料与 AI 执行流程整理成一套可复用 harness。

它不是新的主规则入口，也不替代 `AGENTS.md`、`DEVELOPMENT.md` 或 `standards/*`。执行时仍以 `AGENTS.md` 为唯一主入口，本文件只负责把“读什么、何时读、怎么判断、怎么交付”串成一条稳定路径。

## 当前规则承接说明

旧入口中的有效实践规则必须按职责承接到当前规则链，不允许因为入口删除或工具适配层调整而判定规则失效。

当前职责口径：

- `AGENTS.md` 负责主入口、MCP 使用偏好、执行状态、强制闸门、交付边界和高风险红线。
- `DEVELOPMENT.md` 负责页面结构、抽屉实现、列表页收口、接口标识、toast 反馈、遮罩方案和代码规模边界。
- `standards/*` 负责结构化机检与专项约束。
- `.codebuddy/rules/*`、`.codex/skills/*`、`.agents/skills/*`、`.claude/skills/*` 只作为工具适配层或 skill 层，不得重新成为平行母本。

旧入口中的以下规则主题必须在当前职责层保持可执行约束：MCP 使用偏好、列表页禁止重复造轮子、`⚡` 接口说明使用边界、列表/详情/弹窗短反馈默认 toast、既有功能视觉遮罩方案 D、代码行数历史风险口径。

冲突裁决：

- 抽屉宽度以当前 `standards/doc-spec.json`、`standards/ui-consistency-rules.json`、`ui-spec.json` 的 `780px` 为准；历史 App / 小程序 `620px` 只作为历史兼容信息。
- 既有功能视觉遮罩完整规则见 `harness/rules/既有功能视觉遮罩细则.md`；默认方案 D，完全遮住须用户明确要求。
- 迭代需求分组导出（触发词：新增下载功能 / 把下载做了 / 下载需求包 / 导出需求）完整规则见 `harness/rules/需求分组导出能力.md`；命中即视为该能力 L3 授权，导出口径=只含当前迭代需求区块。
- 旧 `Codex-执行规则.md`、`CodeBuddy-固定前置提示词.md` 不作为主入口；其有效规则必须迁移进当前主入口或专项文件。

## 适用场景

- 新 AI 或新会话需要快速接入本设计稿治理项目。
- 用户要求全局理解项目规则、资料和执行边界。
- 需要判断一个需求应走讨论、方案、页面执行、文档执行、故障排查还是治理同步。
- 需要决定是否引入 `cc-sdd` 这类规格驱动流程。

## 对话握手

完整定义见 `AGENTS.md#对话称呼握手规则`；“山”仅是可见握手词，不能替代规则读取、授权或验证证据。

每轮先判断用户当前处于哪种状态：

| 状态 | 触发口径 | 允许动作 |
| --- | --- | --- |
| 分析执行态 | “看看”“帮我看下”“审一下”“查一下”“分析一下”“有没有问题” | 必须读取相关文件、检索依据、对照规则并输出结论、风险、建议和待确认项；不得修改文件 |
| 分析执行态·疑问句式 | 用户以“能不能”“可不可以”“是否可行”“是否合适”等疑问句式提问时，默认进入分析执行态；即使后续附带了方案描述，只要同句未给出明确执行动词与对象，仍按分析态处理。疑问句的目的是让 AI 分析供用户决策，不是授权 | 只输出方案分析、影响范围、风险、建议与待确认项；不得修改文件；如需执行，必须先向用户确认方案，待用户给出明确执行授权后再进入文件执行态。**涉及页面 UI、颜色、字体、布局等视觉问题时，必须先运行 `design-taste-frontend` 与 `ui-ux-pro-max` 分析，并按 `neat-freak` 做对抗式审查，以 impeccable 标准输出多方案对比**，供用户选择；完整工作流与 skill 清单见 `doc/UI-设计工作流.md` |
| 纯讨论态 | “怎么看”“方案是什么”“是否需要”“对比一下”且未要求读取仓库或生成交付物 | 只输出理解、影响范围、方案、风险、待确认项 |
| 文件执行态 | 命中 `standards/授权词表.md` 定义的 L3 明确授权 | 按开工声明和 preflight 后修改文件 |
| 排障态 | “坏了”“点不了”“报错”“机检失败”“页面异常”；以及“没变”“还是一样的”“毫无变化”“没效果”“还是空”等反馈执行结果不符合预期 | 先复现和定位，再最小修改；收到无效反馈后默认不直接进入下一轮修改，必须先输出问题定位结论 |
| 治理态 | “整理规则”“同步文档”“收口”“新人上手” | 梳理资料层级，避免新增平行规则 |

用户未明确进入文件执行态时，不得修改代码、文档、脚本或删除文件。用户要求“输出一个 md / 落报告 / 生成清单 / 写入文档”时，默认进入文件执行态，但只允许新增或修改该交付文档，不得顺手改现有规则正文。

状态判定以最新用户消息为准。上一轮计划、上一轮授权、AI 自己刚才说过“接下来要改”、或旧会话摘要中的执行结论，不得覆盖最新用户消息。最新消息出现“先讨论 / 怎么优化 / 你没懂 / 谁让你改 / grill me / 审阅 / 看看”等非执行口径时，必须切回非文件执行态，除非同一条消息同时给出明确修改授权。
