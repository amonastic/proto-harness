# 需求分组导出能力

> 触发词：`新增下载功能`、`把下载做了`、`加下载`、`下载需求包`、`导出需求`（指向迭代需求分组的整页导出能力时命中）
> 归属：2026-09-09 用户裁决沉淀（外置细则，由 `harness/00-执行总入口.md` 钩子行触发）
> 开发逻辑文档：`doc/平台管理/20260909-需求分组下载导出能力-开发逻辑.md`
> 最后更新：2026-09-09

## 授权口径

当用户指令命中触发词且指向迭代需求导出能力时，视为用户已就该能力给出 L3 明确授权（2026-09-09 用户原话：「后续新增的页面可以在我说类似于新增下载功能、把下载做了之类的，可以直接执行开发」），可直接进入文件执行态；仍须履行 `AGENTS.md` 开工声明、脏工作区分层与验证闸门。

## 执行基线

1. 双载体：
   - 运行时实时导出（首选）：`assets/js/requirement-exporter.js`。迭代索引页下载入口点击时现场抓取分组内源页面、内联全部资源后触发下载——下载即最新，不存在过期问题。入口写法：`onclick="if(window.RequirementExporter){event.preventDefault();RequirementExporter.download('{分组名}');}"`，`href`/`download` 属性保留作为无脚本环境兜底。需 http 环境（线上或 `npm run serve:local`），`file://` 下 fetch 受限。
   - Node 批量预生成：`npm run export:requirement`（`scripts/export-requirement-group.js`），输出根级 `需求导出/{迭代}-{分组}.html`，用于离线直接转发。生成动作：`node scripts/export-requirement-group.js 迭代索引/{迭代}.html --group {分组名}`；不带 `--group` 列出分组，`--all` 生成全部分组。
2. 分组结构识别：迭代页 DOM 的 `nav-group` / `nav-group-title` / `nav-item[data-page]` / `#page-{id} iframe`；入口 src 可带 query（如 `?view=order` 复用挂载），两个载体都通过 URLSearchParams 垫片注入，页面读参逻辑不变。
3. 下载口径：真下载（`download` 属性 / Blob 触发），禁止做成 `target="_blank"` 打开预览（2026-09-09 用户纠偏：打开≠下载）；入口 `title` 必须注明「点击实时生成最新」。
4. 导出口径：需求抽屉只保留当前迭代区块，历史版本区块不进导出包。两个载体都注入过滤样式 `details.doc-version-block:not(.doc-version-block-current){display:none!important}`，兼容两种存量形态：doc-builder 生成的 `-history` 类、手写「历史收起」区块（仅 `doc-version-block` 基类）。当前区块必须保留 `doc-version-block-current` 类，否则会被误过滤。
5. 新增页面默认能力：新迭代 / 新页面的分组导出按同一入口范式直接执行，不再逐轮确认方案；只有目标迭代 / 分组无法从上下文确定时才向用户确认一次。
6. 收尾：预生成导出文件只在以下情形重跑一次——用户要求刷新或转发需求包、本轮新增或调整了对应分组的下载入口、交付前用户明确要求复核。其余情况不每轮重复导出，改为在最终回复写明“需求包未刷新”（实时下载入口点击时现场生成，不受影响）。导出后上传清单必须包含被修改的迭代索引页、`assets/js/requirement-exporter.js`（若引用）与导出文件；`需求导出/` 不在机检 htmlTargets 内，不登记 ui-spec。
7. 过期审计：`npm run audit:export-stale`（`scripts/audit-export-stale.js`，已挂入 `check:all`，属默认不跑的宽范围命令）——比对预生成导出文件 mtime 与分组内源页面 mtime，过期即列出受影响源页面并失败退出。报警不阻断实时导出入口（实时导出永远最新），只针对直接转发预生成包的场景；默认按 `harness/05-验证与交付.md#窄验证默认口径` 收敛执行时机，不需要每轮跑。

## 禁止行为

- 不得把导出文件当业务页面处理或登记进 ui-spec。
- 不得修改历史迭代 / 快照来生成导出；历史迭代导出必须基于快照内容，当前未启用，需要时另立任务。
- 不得让导出包绕过页面正文边界：页面内不得混入开发备注、测试提示等设计稿可见信息。

## 已知边界与反例

- 非版本分层抽屉（无 `doc-version-block` 结构）无法程序化区分历史内容，导出时整包保留；如需过滤须先把该页抽屉改造为版本区块分层。
- 业务功能内的普通下载 / 导出（如列表导出 Excel、模板下载）是普通需求，不走本规则。
- 「把下载做了」但当前会话没有迭代上下文：默认当前最新迭代全部分组；无法确定分组名时确认一次，不得猜测。
