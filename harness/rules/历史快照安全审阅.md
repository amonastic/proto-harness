## 历史快照与迭代引用安全审阅

当任务涉及以下任一内容时，指导审阅者或其他第三方审阅者必须追加历史快照安全审阅：

- 修改 `迭代索引/*.html`
- 修改 `迭代索引/snapshots/**`
- 修改被历史迭代引用的源页面
- 修改快照依赖的 `js/docs.js`、`js/doc-panel.js`、页面私有 JS/CSS
- 新增快照、删除快照或切换 iframe 指向
- 运行或计划运行可能影响历史页面引用关系的治理动作

必读依据：

1. `AGENTS.md` 中的 T-1 历史快照不可污染红线
2. `harness/01-强制闸门.md`
3. `harness/03-任务契约.md` 中的目录引用、快照、`clone-source` 和 `change-type` 规则
4. 当前迭代页、快照页、源页面及其 `docs.js` / `doc-panel.js`

强制检查：

1. 列出本轮实际检查范围，不得只写“已检查快照”。
2. 枚举迭代页 iframe 指向，区分活页源与 `snapshots/{迭代}/` 冻结快照。
3. 对每个快照检查 `snapshot-of`、`snapshot-iteration`、`snapshot-date`；`clone-source`、`change-type` 缺失虽非 T-1 强制项，但会阻断可追溯性。
4. 检查快照是否引用外部可变 `js/docs.js`、`js/doc-panel.js` 或其他仍在演进的源目录资源。
5. 检查 menu、iframe、`pageNames`、footer count 或等效入口数量是否一致。
6. 检查当前 dirty 或未跟踪文件是否直接影响历史快照口径。
7. 所有结论区分 `已确认 / 推断 / 待确认`。

输出：

```text
历史快照安全审阅结论：
本轮实际检查范围：
发现的历史活页引用：
发现的可变 docs/doc-panel 依赖：
发现的快照元信息缺失：
发现的 menu / iframe / pageNames / footer count 不一致：
受当前 dirty 影响的快照或迭代页：
风险等级排序：
最小修正建议：
检查边界：
```

以下任一问题默认属于阻塞风险，不给 `design over`，不声称“已收口”：

- 历史迭代仍 iframe 活页
- 快照依赖外部可变 `docs.js` / `doc-panel.js`
- 快照私有需求说明数据仍处于未核验 dirty
- 快照缺少 `snapshot-of`、`snapshot-iteration` 或 `snapshot-date`
- menu、iframe、`pageNames` 出现未解释的不一致

页面当前能打开不能证明快照安全。证据只足以证明“存在污染风险”时，结论只能到“存在污染风险”，不得自动扩大为整套治理方案。
