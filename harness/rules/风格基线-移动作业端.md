# 移动作业端 App 风格基线

> 非通用 Harness。仅适用于本仓库内 `field-app/main`（移动作业端）设计稿开发。不得直接迁移到其他项目、Web 后台、小程序、驻站作业场景（见补充场景基线）或真实线上前端实现。

## 1. 定位

本文件用于把移动作业端中最接近真实页面的一组成熟页面沉淀成可执行风格基线，供后续设计稿开发、复刻改造、AI 辅助页面实现或修改、ardot MCP 会话与非 ardot 本地会话共同遵循。

本文件不是新的主规则入口，不替代 `AGENTS.md`、`harness/README.md`、`harness/00-执行总入口.md`、`harness/01-强制闸门.md`、`DEVELOPMENT.md` 或 `standards/*`。执行时仍先读 `AGENTS.md`，再按任务类型读取对应规则；本文件只在确认目标属于 `field-app/main` 页面风格时启用。

不得脱离仓库规则、目标页面和 style clone-source 直接生成独立 HTML；AI 只能在已确认项目边界、页面类型、复用来源和静态原型规则后辅助实现或修改。

## 2. 适用范围

适用：

- `field-app/main/pages/*.html` 下的移动作业端页面设计稿。
- 移动作业端的 0-1 页面、既有页面新增、复刻改造、视觉收口。
- 需要让 AI 在 ardot 与非 ardot 环境中保持同一套作业端视觉判断的任务。

不适用：

- `admin-portal` 下门店后台、运维后台、服务站后台等 Web 页面。
- `mini-program` 下小程序页面。
- `field-app/station-ops`（驻站作业场景）页面，除非用户明确指定跨模块复用且另行声明 clone-source。
- 真实生产前端工程、接口联调、业务状态机实现。
- 外部个人新项目或其他设计系统；外部项目如需复用，应重新抽象为该项目自己的 Harness。

## 3. 与主 Harness 的裁决

- 当目标路径属于 `field-app/main` 时，移动作业端页面风格优先使用本 Harness。
- `harness/10-页面与抽屉执行.md` 中的 App 成熟基准继续服务其他 App 场景。
- 若任务跨 `field-app/main` 与 `field-app/station-ops`，必须分别声明两端 clone-source，并说明哪些结构或视觉只在对应端内生效。
- 本裁决只处理移动作业端风格基准归属，不改变 `AGENTS.md`、`standards/*`、抽屉规则、静态原型边界和验证命令优先级。

## 4. 强制读取顺序

执行移动作业端页面设计稿前，按以下顺序读取：

1. `AGENTS.md`：确认本轮是讨论态、文件执行态、排障态还是治理态。
2. `harness/README.md`：确认 Harness 任务路由。
3. `harness/00-执行总入口.md`、`harness/01-强制闸门.md`：确认 Harness 准入、执行闸门、规则资料地图。
4. 与任务相关的 `standards/*`：
   - 视觉与 token：`standards/design-tokens.json`
   - 平台骨架：`standards/platform-rules.json`
   - 抽屉与一致性：`standards/ui-consistency-rules.json`
   - 复刻边界：`standards/page-baseline-spec.json`
   - 文档抽屉：`standards/doc-spec.json`
4. 本文件。
5. 本文件列出的 style clone-source 页面。
6. 目标页面、模块 js/docs.js、模块级需求文档（如模块实际提供），如任务涉及抽屉或说明。

若任一规则与本文件冲突，优先级为：用户本轮明确要求 > `AGENTS.md` > Harness 最小读取链与任务路由 > `DEVELOPMENT.md` > `standards/*` > 本文件 > 成熟页面局部实践。

## 6. 移动作业端视觉基线

### 6.1 页面壳

- 默认使用 iPhone 设计稿壳：`width: 393px`、`height: 852px`、`border-radius: 50px`。
- 页面外桌面背景多为深色：`#1a1a1a`、`#202020` 或相近深灰；用于突出手机壳，不作为 App 内页面背景。
- 手机壳阴影常见：`0 0 0 12px #333` + 柔和外阴影。
- 手机壳内 `overflow: hidden`，页面内容垂直布局，滚动区域隐藏浏览器滚动条。
- 底部 Home Indicator 常见：宽 `130px` 左右，高 `5px`，底部 `8px`，黑色并带轻透明。

### 6.2 顶部与状态栏

- 状态栏常见高度：`54px`；字体 `15px`、`600`。
- 普通业务页顶部导航为白底，标题 `17px`、`600`，左侧返回按钮约 `32px`。
- 需要强调详情氛围时，可参考 `费用详情.html` 使用蓝色渐变头部，但不得让所有页面默认蓝色大头图。
- 顶部右侧文字入口常用 `14px-15px`，颜色以 `#666` 或主蓝为主。

### 6.3 背景、卡片与层级

- App 内页面背景优先使用 `#F5F7FA` 或 `#f5f5f5`。
- 内容区左右边距通常为 `12px-16px`，卡片间距通常为 `12px`。
- 卡片白底，圆角常见 `8px` 或 `12px`；复杂内容卡片可用 `padding: 14px 16px` 或 `16px`。
- 分割线优先用 `#F0F0F0`、`#E5E7EB`、`#E8E8E8`，避免重边框。
- 列表卡片要保持扫描效率：主信息突出，次级信息弱化，标签小而清楚，不使用装饰性大卡。

### 6.4 色彩

基础色以仓库 token 为准：

- 主色：`#1677FF`。
- 可接受的同族蓝：`#3B82F6`、`#1890ff`、`#0966D9`，仅在 clone-source 已出现或用于渐变收口时使用。
- 页面背景：`#F5F7FA`。
- 卡片背景：`#FFFFFF`。
- 主文本：`#1A1A1A`、`#111827`、`#333`。
- 次级文本：`#666`、`#6B7280`。
- 辅助文本：`#999`、`#9CA3AF`。
- 成功语义：`#00B578`、`#059669`。
- 危险语义：`#FF4D4F`、`#EF4444`。
- 警告提示条：背景 `#FFF7E6`，图标/强调 `#FAAD14`，文案 `#D48806`。

不得为同一语义新增一套无依据颜色。若页面 clone-source 与 `standards/design-tokens.json` 不一致，优先用 token 定语义，用 clone-source 收紧视觉。

### 6.5 字体与字号

- 字体族默认：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Helvetica Neue", Arial, sans-serif`。
- 页面标题：`17px-18px`，`600-700`。
- 分组标题：`15px-16px`，`600`。
- 正文：`14px-15px`。
- 辅助说明：`12px-13px`。
- 标签、状态、角标：`10px-12px`。
- 数字强调可使用 `"DIN Alternate"` 或 `"Roboto"`，但仅用于数量、金额、编号等明确数字信息。
- 表单配置区（输入框、只读字段、分隔符、选择值）字号统一 `14px`，不得大于设置行标题（`15px`），避免配置区视觉偏大。
- 字重：页面标题、分组标题才使用 `600-700`；正文、输入值、只读值、小标签默认 `400`，次级强调允许 `500`，不得在输入框、只读块、标签上滥用 `600/700`。

### 6.6 按钮与底部操作

- 主按钮优先蓝底白字，常见高度 `44px-48px`。
- 圆角根据场景选择：
  - 普通表单/设置按钮：`8px` 左右。
  - 底部胶囊主按钮：`24px` 左右。
  - 小标签/小按钮：`4px-10px`。
- 底部操作栏白底固定，保留安全区，常见 `padding-bottom: calc(10px + env(safe-area-inset-bottom, 20px))` 或页面内显式底部留白。
- 底部只保留当前页面核心动作，不顺手新增快捷入口、统计条、解释卡片。

### 6.7 表单、设置与选择

- 设置行白底分组，行高稳定，右侧放当前值、箭头、开关或状态。
- 输入区使用浅灰背景或白底细边框，圆角 `6px-8px`。
- 开关选中态用主蓝，未选中态用灰色。
- 单选/金额选择的选中态用蓝色边框、浅蓝背景或蓝色填充；同一页面内保持一种模式。
- 预览区域可用浅灰底承载，预览卡片白底，视觉层级要弱于正式业务卡片。
- 配置行内字段须与卡片内容区两端对齐（不额外缩进），元素水平/垂直居中不依赖内容高度；块状字段（输入、只读、引用卡）显式 `height` 统一（如 `44px`）并用 `box-sizing: border-box`。
- 只读字段与可输入字段必须视觉可区分：只读用更深一档灰底（如 `#EEF0F3`）+ 浅灰字（如 `#8A9099`）弱化非交互感；输入用浅底（如 `#F5F7FA`）+ 深字（如 `#333`）强调可编辑感。
- 预览区、提示条行距克制：预览区上下 `padding` 不超过 `16px`；提示条 `13px`、行高 `1.6`；不得为撑高度滥用大内边距。

### 6.8 提示与异常

- 警告提示条参考 `自定义类型设置.html`：浅橙背景、左侧警告图标、正文 `13px`、行高 `1.6`、右侧关闭按钮。
- 提示条只承载用户必须知道的业务影响，不承载开发备注、需求说明、测试提示或设计稿说明。
- 真实页面正文不得出现“模拟操作”“仅设计稿可见”“开发备注”“测试按钮”“场景切换器”等文案。

### 6.9 需求文档与 CSS 规范抽屉

- App 默认遵循 `platform-rules.json`：`docPanelMode: auto-open`。
- 需求文档入口可使用右侧独立按钮或公共 `dg-doc-btn` / `doc-button.js`，不得挤入真实 App 页面内容。
- 需求文档 Tab 与 CSS 规范 Tab 仍按 `standards/ui-consistency-rules.json` 与 `standards/doc-spec.json` 执行。
- CSS 规范至少能表达颜色、字体、圆角、间距，并优先读取页面级 `getDocCssContent(docId)`。
- 如果说明来自模块 `js/docs.js`，最终交付和上传清单必须单独列出该 JS 文件。

## 7. 页面类型执行模板

### 7.1 列表页

参考 `订单列表.html`：

- 顶部状态栏 + 内容滚动区 + 底部固定动作栏。
- 列表项用白色卡片承载，核心编号、状态、标签先于次级信息。
- 状态标签小尺寸、低噪声；同类状态颜色保持一致。
- 批量动作放底部或明确操作区，不在每张卡片上堆满按钮。

### 7.2 详情页

参考 `费用详情.html`：

- 可使用顶部蓝色渐变增强页面归属，但只在详情/费用类页面按需使用。
- 地址、费用、明细等信息分白卡展示。
- 关键金额和费用结果突出，辅助说明用浅色块或小字号。
- 底部只保留一个主动作或清晰主次动作。

### 7.3 设置页

参考 `偏好设置.html` 与 `自定义类型设置.html`：

- 白底设置行分组，内容区背景 `#F5F7FA`。
- 选择、开关、输入、预览按业务逻辑从上到下排列。
- 警告提示只在存在用户影响时出现，不把需求背景写进页面。
- 底部保存按钮固定或靠底，避免被滚动内容遮挡。

### 7.4 打印/预览页

参考 `凭证号打印.html`：

- 设置项先于预览；预览区独立且弱于主操作。
- 预览卡片需要稳定尺寸，切换或选中态不得造成布局跳动。
- 底部打印按钮是主动作；未连接、不可用等状态必须有明确视觉区分。

### 7.5 钱包/支付页

参考 `钱包充值.html`：

- 账户信息、金额选择、支付方式分区展示。
- 金额网格间距稳定，选中态清楚但不过度装饰。
- 支付方式单选行保留图标、名称、选中态，不混入长说明。
- 底部按钮文案可携带当前金额，但金额来源必须来自页面已有需求或用户确认。

## 8. ardot 使用流程

在 ardot MCP 会话中使用本 Harness 时，必须先让模型明确以下约束：

```text
你正在本仓库内生成或修改移动作业端（field-app/main）设计稿。
本次不是通用 HTML 生成任务。
先读取 AGENTS.md、harness/README.md、harness/00-执行总入口.md、harness/01-强制闸门.md、standards 相关规则和 harness/rules/风格基线-移动作业端.md。
再读取目标页面和本 Harness 的 style clone-source。
只复用移动作业端页面壳、视觉密度、组件层级和抽屉规则，不复用未确认业务字段、状态或接口。
若目标不是 field-app/main 页面，停止套用本 Harness。
```

执行步骤：

1. 先发现 ardot 当前暴露的 MCP 工具或资源，确认是否具备读取文件、批量读取、截图或页面检查能力；具体工具名以 ardot 实际暴露结果为准。
2. 先读取规则，不直接让大模型“生成一个 HTML”。
3. 批量读取目标页面、目标模块说明和本 Harness 第 5 节选定的 style clone-source。
4. 如 ardot 支持截图或预览，先获取目标页面和 clone-source 的截图；不支持时，以现有 HTML/CSS 为主要证据。
5. 确认页面类型、业务边界、clone-source、change-type、允许新增范围后再改稿。
6. 输出前检查：页面壳、背景、卡片、按钮、底部安全区、抽屉入口、真实页面文案边界。
7. 如果模型提出跨端通用建议，必须改写为“仅当前移动作业端适用”或删除。

## 9. 非 ardot 使用流程

不通过 ardot 时，仍按本 Harness 执行：

1. 用本地文件读取目标页面和 clone-source 页面。
2. 用 `rg` 定位 `.iphone-frame`、`.status-bar`、`.header`、`.content`、`.bottom-section`、`.home-indicator`、`DocPanel`、`getDocCssContent` 等结构。
3. 对照 `standards/design-tokens.json` 与本文件的视觉基线，先定页面壳和结构，再补局部样式。
4. 只做当前任务需要的最小增量，不重写无关页面，不批量迁移样式。
5. 文档或治理类修改至少运行 `git diff --check`；页面类修改优先运行最窄相关检查。

## 10. 禁止项

- 禁止把本 Harness 当成通用产品设计规范。
- 禁止脱离仓库规则、目标页面和 style clone-source 直接生成独立 HTML。
- 禁止用本 Harness 覆盖小程序、Web 后台、驻站作业场景或其他项目。
- 禁止只凭本文件生成新业务字段、状态流转、接口参数或金额规则。
- 禁止把需求说明、开发备注、测试提示、模拟操作写进真实页面正文、业务弹窗或业务抽屉。
- 禁止为了“更完整”顺手新增筛选器、统计条、快捷入口、说明卡片或新模块区块。
- 禁止机械平均 6 个页面的 CSS 数值；应按目标页面类型选择最接近 clone-source。
- 禁止将单个页面的蓝色渐变头部、警告条、金额网格、打印预览强行套给所有 App 页面。

## 11. 验证清单

页面或文档完成前，至少检查：

- 是否仍以 `AGENTS.md` 为主入口，本文件没有替代项目规则。
- 目标是否确认为 `field-app/main`；否则不得套用。
- 是否声明了 style clone-source 和 change-type。
- 手机壳是否保持 393×852、圆角约 50px、底部 Home Indicator、滚动区不露浏览器滚动条。
- 页面背景、卡片、按钮、标签、提示条是否落在本 Harness 与 token 允许范围。
- 顶部状态栏、标题、返回按钮、底部安全区是否与成熟页面接近。
- 真实页面正文是否没有混入需求说明、开发备注、测试提示、模拟操作。
- 需求文档与 CSS 规范抽屉是否按 App 默认 auto-open 和项目抽屉规则执行。
- 文案是否不溢出、不遮挡、不把按钮或标签撑变形。
- 新增内容是否只服务本轮需求，没有顺手扩展业务范围。

治理文档类修改验证命令：

```bash
git diff --check -- harness/rules/风格基线-移动作业端.md
```

页面类修改根据范围选择：

```bash
npm run check:ui
npm run audit:docs
npm run check:all
```

## 12. 输出格式

当 AI 使用本 Harness 输出方案或最终回复时，必须区分：

- 本地已修改的文件。
- 依据的 clone-source。
