# 强制闸门

本文件承载每轮执行前后必须通过的通用闸门，适用于讨论、执行、排障、治理和收尾。

## 强制执行闸门

任何会修改文件的任务，必须先完成以下闸门；任一项缺失，不得动手：

1. 状态判定：分析执行态 / 纯讨论态 / 文件执行态 / 排障态 / 治理态。
2. 修改声明：本轮准备修改的文件。
3. 禁止范围：本轮不修改的文件、页面、规则或脚本。
4. 已读规则：列出已读取规则文件；不可用 skill 必须说明替代方案。
5. 当前规则证据：列出当前生效入口和本轮实际读取的本地规则文件；不得用“已读规则”“按 Harness”替代文件路径和一句话读后约束。Harness、`AGENTS.md` 或规则入口刚修改、回退、被审阅或被用户质疑时，必须重新读取当前文件，旧会话记忆不得作为当前规则证据。
   - 握手词定义见 `AGENTS.md#对话称呼握手规则`；以“山”开头只证明命中握手词，不证明通过 Harness。
   - 当任务涉及文件修改、跨会话接力、规则审阅、需求交付或用户质疑 Harness 时，必须同时提供可核验证据：当前规则读取证据、本轮授权原文、目标文件与禁止范围、验证计划或验证结果。缺任一项时，不得视为通过 Harness；执行者必须先补齐证据，补不齐只能进入讨论、分析或排障，不得继续修改或声称完成。
6. 本轮授权原文：逐字摘出用户本轮明确授权修改或交付的原话。无法摘出 `standards/授权词表.md` 定义的 L3 明确授权时，不得修改文件。
7. 执行依据：用户要求、现有页面、需求文档、接口文档、clone-source。
8. 任务画像：0-1 / 普通迭代 / 微调 / 纯抽屉 / 复刻改造 / design over / 治理。
9. 交互授权：是否允许新增交互、提示、测试项、验收项；未明确即不允许。
10. 复刻信息：涉及复刻时必须写 `clone-source`、`change-type`、保护项和允许新增项。
11. 入口闭环：涉及页面新增或可见性时，必须列出入口闭环检查对象。
12. 验证计划：预计运行的最窄命令；不运行的检查需说明原因。默认只跑与改动文件直接相关的窄验证，不默认跑 `check:all`、`audit:ui`、`audit:docs`、`audit:snapshots`、需求导出与导出过期审计；不得用 `pkill` / `killall` 按进程名结束本地预览服务。完整口径见 `harness/05-验证与交付.md#窄验证默认口径`、`harness/05-验证与交付.md#本地服务保护`。
13. 重试上限：同一文件同一问题连续两轮修改无效时，必须停止继续猜测，转为诊断报告，列出已尝试方式、失败现象、下一步验证路径；第三轮仍无效时，必须等待用户确认后再继续。
14. Skill 确认：任务类型判定后，必须按 Skill 路由表确认是否需要触发对应 skill；若 skill 不可用，必须说明替代的手工流程，不得静默跳过。
15. 脏工作区保护：文件执行态开始前必须检查 `git status --short` 或等效本地差异来源；列出本轮目标文件、已有非本轮改动和禁止触碰范围。不得回滚、覆盖、整理或顺手提交非本轮改动。只要 `git status --short` 出现非本轮 dirty 或未跟踪文件，必须先按 `本轮目标文件 / 本轮依赖但不修改文件 / 既有非本轮 dirty 文件 / 高风险禁止触碰文件 / 未跟踪文件` 分层；不得以“改动不多 / 看起来相关 / 顺手一起提交”为理由跳过。高风险禁止触碰文件至少包括历史迭代、`迭代索引/snapshots/**`、`AGENTS.md`、Harness、`standards/**`、`templates/**`。
16. 读后回执：执行者不能只写“已读规则”。每个必读文件必须用一句话说明它对本轮的具体约束；无法读取时必须说明失败原因和替代材料，不得假装已读。
17. 接力材料分层：分层定义与处理边界见 `harness/02-纠偏与接力.md#跨会话事故复盘与接力准入`；未完成五分层不得修改文件。
18. 子 agent 独立授权核验：凡由父 agent、指导者或其他会话委派的子 agent，在准备任何文件写入前，必须自行读取当前项目规则与 `standards/授权词表.md`，逐字核验用户最新一条消息中的 L3 授权原文、授权对象、目标文件、禁止范围和交互授权。父 agent 的任务包、发包消息、口头指令、角色切换、上一轮授权、接力摘要以及“改吧”等未命中 L3 的表达，均不得转化为文件授权；无法确认授权覆盖目标时，子 agent 只能输出只读审查结果并停手。子 agent 不得以“父 agent 已通过闸门”替代自身核验，父子双方均须保留各自授权证据。
19. 页面调整契约：涉及页面、抽屉、需求说明、字段、按钮、状态、文案、布局、跨页同步或复刻改造时，必须先生成逐页页面调整契约；契约未闭环不得修改文件。
19. 新增页面落位：涉及新增页面、复制页面、复刻页面或新增入口时，必须先判定 `source-page` 还是 `iteration-reference`，并声明源文件路径、源目录入口和是否需要迭代引用。
    - 除非用户本轮明确要求不在源目录菜单展示，否则每个新增业务页面文件必须与源目录前端菜单或导航条目在同一任务切片完成，并补齐承载区或 `href`、`pageNames` / 面包屑和 URL 参数映射；执行者、任务包、旧文档或页面引用均无权自行豁免。
    - 新增菜单或导航条目必须展示页面已确认所属迭代的完整月份标签 `YYYYMM上` / `YYYYMM下`，并与目录分组、页面注释、`pageNames` 和迭代归属一致；无依据时不得猜测月份，也不得先创建页面再把菜单或标签留作待确认。
    - 真实前端注册必须在源文件所属源目录的前端菜单或导航完成；迭代页、专项聚合页、总导航、搜索索引或登记清单中的引用不得代替源目录注册。仅当现有页面类型、落位规则或仓库事实确认源文件本身合法位于迭代页时，才允许把该迭代页自身的菜单或导航闭环作为注册证据，但仍须展示完整月份标签；不得由普通引用关系反推此例外。
    - 新增业务页面已创建但源目录菜单、完整月份标签或路由承载任一缺失，属于入口闭环硬失败：不得交付、不得标记完成、不得给出 `design over`。只有用户本轮明确授权的“不在源目录菜单展示”例外可以跳过菜单和菜单月份标签，其他入口与迭代引用规则继续适用。
    - 新增迭代快照页前必须先确认是否存在对应源页面与源目录入口；除非用户明确要求“只修历史快照 / 仅修快照污染”，不得在 `迭代索引/snapshots/**` 中凭空新增业务页面。
    - 若快照承接的是本期业务页面，应先补齐或修正三端源页面、源 `index.html` 菜单 / iframe / `pageNames` / 面包屑 / URL 参数映射，再冻结到对应快照目录。
    - 源页面与快照页面同时存在时，需求抽屉数据源必须同步检查；不得只改快照 docs 或只改源 docs 后声称本期口径已收口。
20. 迭代引用策略：新增或调整源页面后，必须声明不挂迭代 / 挂当前迭代 / 进入待排期 / 冻结历史快照；无法判断时必须向用户确认，不得擅自写入某个迭代页。
21. 目录分组一致性：涉及源目录或迭代目录时，必须检查分组标题、条目标签、iframe 注释、`pageNames`、页脚数量是否同口径；发现旧目录串期只能报告或进入单独治理任务。
22. 截图复刻矩阵：用户提供截图时，必须列出截图直接复刻项、按当前端成熟风格适配项、不可凭截图写成事实项、待确认项，并逐字段核对可见内容。用户说“复刻图 / 按图”默认只允许复刻信息结构、可见业务文案、字段顺序和操作层级；不得擅自改变当前页面或弹窗的整体宽高、字号比例、圆角、遮罩方式、底部栏高度、页面密度或视觉风格。只有用户明确说“尺寸也照图 / 比例也照图 / 1:1 复刻”，才允许调整整体尺寸比例。
23. 页面可见文案剔除清单：涉及真实页面、业务弹窗或业务抽屉时，必须列出本轮不得进入用户可见区域的需求说明、开发说明、后端说明、测试提示和执行者说明关键词；最终交付前必须搜索目标文件或验证 DOM 不含这些词句。强制剔除词至少包括：`后端`、`接口`、`适配`、`复用能力`、`失败明细`、`更新策略`、`开发`、`测试`、`需求说明`、`仅设计稿`、`模拟操作`、`执行者`。若这些词确属页面真实业务文案，必须写明用户原话或既有页面依据，否则不得进入真实页面、业务弹窗或业务抽屉。
24. 可见改动证据闭环：任何声称页面可见改动已生效的任务，必须计划并执行真实入口或源页面打开、目标入口触发、DOM 状态读取、截图确认；无法执行时必须在最终回复中降级为“代码已改，页面可见效果未验证”。
25. 决策与不确定性闸门：涉及范围取舍、是否执行、是否打标、是否新增页面、是否改全局规则或是否继承旧结论时，必须先完成“不确定性台账、决策类型、范围裁剪矩阵、最小验证切片”。不得把信息不足包装成可执行方案。
26. 可逆性判断：必须标明本轮决策属于 `可逆` / `半可逆` / `高污染或不可逆`。可逆项也必须填写不确定性台账和范围裁剪矩阵，只是允许字段写 `无 / 不适用`；半可逆项必须有页面调整契约或规则写入准入；高污染或不可逆项默认结论为“需用户确认后执行”。
27. 最小验证切片：当任务存在多个未知或多个页面/端/规则面时，必须优先提出最小可验证切片。切片必须具体到文件、页面、docId、命令、DOM 验证对象或规则章节；不得只写“先小范围验证”。
28. 闸门空跑失败：不确定性台账、决策类型、范围裁剪矩阵、最小验证切片任一字段留空、只写“已处理 / 无问题 / 按需处理 / 后续确认”，视为未通过闸门；未通过时不得修改文件。
29. 平台入口嵌套拦截：迭代索引、专项聚合页等承载页不得在 iframe 中嵌入带 `system-nav` / 平台侧边栏的 `index.html` 入口页，避免出现双侧边栏、双菜单、双面包屑。需要引用具体页面时，必须优先 iframe 叶子页面 `pages/*.html`；若必须通过入口页定位子页面，源入口必须先支持无侧边栏嵌入模式并完成截图验证。未具备嵌入模式时，只能使用同步说明弹窗，不得 iframe 入口页。

## 闸门三级分级表

本表只决定执行时机，不降低、不替代、不豁免上述 29 条闸门的原文约束。

- L1 可逆：仅适用于原本在执行中或执行后才触发的闸门；先执行相应动作后审计，不得违反原文已有前置限制。
- L2 半可逆：执行前声明意图与回滚或降级方式，不需额外等待批准。
- L3 高污染或不可逆：必须取得用户本轮明确授权词后才可执行；无授权即阻断。

| 闸门 | 等级 | 执行时机 | 定级理由 |
| --- | --- | --- | --- |
| 1. 状态判定 | L2 | 动手前 | 状态误判会让后续动作越权，但可在写入前通过重新判定纠正。 |
| 2. 修改声明 | L2 | 动手前 | 先锁定目标能约束写入范围，遗漏仍可在实际修改前补齐。 |
| 3. 禁止范围 | L2 | 动手前 | 明确边界可阻止顺手扩写，属于写入前可控的范围风险。 |
| 4. 已读规则 | L2 | 动手前 | 规则未读会导致执行偏差，但读取与补充说明在写入前可逆。 |
| 5. 当前规则证据 | L2 | 动手前 | 当前入口证据防止沿用失效规则，应在行动前建立且可补正。 |
| 6. 本轮授权原文 | L3 | 动手前；无授权即阻断 | 文件写入改变用户资产，必须以本轮明确授权保护用户决策权。 |
| 7. 执行依据 | L2 | 动手前 | 依据不足会造成错误实现，但可通过补查本地证据后缩小或撤回方案。 |
| 8. 任务画像 | L2 | 动手前 | 画像影响适用规则与边界，错误分类应在实施前修正。 |
| 9. 交互授权 | L3 | 新增交互、提示、测试项或验收项前 | 新增可见行为会改变交付范围，未经用户明确允许不得引入。 |
| 10. 复刻信息 | L2 | 复刻改造前 | 复刻来源与变更类型可在动手前限定，避免把参考误当成业务事实。 |
| 11. 入口闭环 | L2 | 新增页面或改变可见性前 | 入口遗漏会留下不可达页面，但可在发布前补齐或回退关联。 |
| 12. 验证计划 | L2 | 动手前 | 预先定义最窄验证能及早发现偏差，检查方案本身可按风险调整。 |
| 13. 重试上限 | L1 | 同一问题连续失败后、再次尝试前 | 它只在既有尝试失败后触发，用于止损并审计后续诊断路径。 |
| 14. Skill 确认 | L2 | 动手前 | 专项能力遗漏会降低判断质量，但可在实施前补用 skill 或手工替代流程。 |
| 15. 脏工作区保护 | L2 | 文件执行态开始前 | 脏文件误伤风险可通过先分层、后操作控制，尚未写入前可恢复边界。 |
| 16. 读后回执 | L2 | 动手前 | 读后约束显性化可暴露误读，遗漏可在实施前补齐。 |
| 17. 接力材料分层 | L2 | 引用接力材料并写入前 | 分层可阻断把未经验证的结论写成事实，且可在写入前重新核验。 |
| 18. 页面调整契约 | L2 | 页面、抽屉或文案改动前 | 契约把可见改动拆为可审查项，未闭环时仍可收缩或暂停。 |
| 19. 新增页面落位 | L3 | 新增、复制、复刻页面或新增入口前 | 页面与入口会形成长期目录和快照影响，必须在用户授权的范围内落位。 |
| 20. 迭代引用策略 | L3 | 新增或调整源页面、迭代或快照引用前 | 引用决策可能污染历史迭代或改变发布口径，需用户明确授权后执行。 |
| 21. 目录分组一致性 | L2 | 变更源目录或迭代目录前 | 分组不一致可导致导航错位，但可通过核对并回退局部目录改动修复。 |
| 22. 截图复刻矩阵 | L2 | 截图复刻前 | 矩阵先区分可见事实与推断，能在实现前防止无依据扩写。 |
| 23. 页面可见文案剔除清单 | L2 | 真实页面改动前及交付前 | 不当文案外露可由写入前清单和交付前搜索拦截，问题可局部撤回。 |
| 24. 可见改动证据闭环 | L1 | 可见改动后、交付前 | 它验证已发生的页面变化并决定交付表述，不是开始修改的前置动作。 |
| 25. 决策与不确定性闸门 | L3 | 全局或高影响决策前 | 全局规则、历史与跨端决策的外溢成本高，必须先由用户明确授权。 |
| 26. 可逆性判断 | L3 | 高污染或不可逆操作前 | 对高污染动作的分类决定是否可继续，分类不清时必须停在授权之前。 |
| 27. 最小验证切片 | L2 | 多未知、多页面、多端或多规则面动手前 | 先压缩验证面能限制试错扩散，切片失败时可安全停下诊断。 |
| 28. 闸门空跑失败 | L2 | 开工审查完成时 | 它检查前置材料是否只是形式填写，未通过时可补齐材料而不必扩大改动。 |
| 29. 平台入口嵌套拦截 | L3 | 改变 iframe 承载结构前 | 嵌套入口会影响全局导航和历史承载体验，错误外溢广且不应擅自执行。 |

确不涉及的闸门项必须标为“不适用”并说明原因，不能省略。

任何会改文件的任务，在修改前必须先完成执行前审查。即使当前工具不支持 skill，也必须按 `design-task-preflight` 的字段手工输出审查结果。

发现规则冲突时，执行前必须输出冲突裁决：冲突项、涉及文件、采用哪条、放弃哪条、原因。未输出冲突裁决时，不得修改文件。

若实际修改范围超出开工声明，必须停下重新声明并等待用户确认；不得在最终回复中才补充解释。

## 决策与不确定性闸门

本闸门用于吸收外部产品决策类 skills 的有效部分：先识别不确定性、判断决策可逆性、裁剪范围，再决定是否执行。它不引入新的主入口，也不替代 `design-task-preflight`；只补足执行前的判断质量。

### 触发场景

出现以下任一情况，必须启用本闸门：

- 用户问“能不能升级 / 要不要做 / 是否值得 / 怎么取舍 / 是否可打标 / 是否直接改”。
- 任务包含多个页面、多个端、多个规则文件、历史快照、全局组件、公共脚本或跨会话接力材料。
- 当前依据来自截图、上一位 AI 结论、旧文档、审计摘要、外部仓库、用户强纠偏或不完整需求。
- 执行后可能污染历史快照、入口目录、公共能力、全局 harness、`design over` 结论或跨端业务口径。

### 不确定性台账

先按类型列出未知项，并给出处理方式：

```text
不确定性台账：
技术未知：
业务口径未知：
页面承载未知：
历史接力未知：
用户裁决未知：
处理方式：查文件 / 查页面 / 查规则 / 查命令 / 问用户 / 降级为待确认 / 禁止执行
```

规则：

- 每一类未知必须填写为 `无` / `已确认：依据` / `未确认：处理方式` / `阻断：原因` 之一；不得留空，不得只写“已处理 / 无问题 / 已确认”。
- 能通过本地文件、页面、规则或命令确认的，不得直接问用户。
- 不能确认但不影响当前最小切片的，必须降级为 `待确认`，不得写成事实。
- 会影响字段、状态、权限、入口、历史快照、公共能力或 `design over` 的未知项，必须先确认或阻断执行。

### 决策类型

执行前必须判断：

| 类型 | 例子 | 默认处理 |
| --- | --- | --- |
| `可逆` | 文案微调、抽屉补充、局部样式修正、非关键说明调整 | 可小步执行，但仍需填写不确定性台账、范围裁剪矩阵、依据和验证 |
| `半可逆` | 页面结构、入口目录、字段新增、需求抽屉结构、跨页同步 | 必须有页面调整契约、范围裁剪和验证计划 |
| `高污染或不可逆` | 历史快照、公共组件、全局规则、跨端口径、`design over` 打标、批量目录治理 | 必须先输出风险、替代方案、用户确认点；未确认不得执行 |

高污染或不可逆任务即使已经输出风险和替代方案，也不得自动进入文件修改；只有用户本轮明确授权，且不确定性台账中所有阻断项均为 `无`，才允许继续。

### 范围裁剪矩阵

复杂任务不得只写“按需处理”。必须先裁剪：

```text
范围裁剪矩阵：
必做项：
可推迟项：
明确不做项：
需要用户裁决项：
禁止 AI 自行扩展项：
最小验证切片：
```

规则：

- `必做项` 必须能直接追溯到用户要求、现有文件、规则或成熟页面。
- `可推迟项` 不得在本轮顺手完成。
- `明确不做项` 和 `禁止 AI 自行扩展项` 必须同步进入开工声明的禁止范围，并在最终回复说明未触碰，防止接力模型重新补回。
- `最小验证切片` 必须写清具体文件、页面、docId、命令、DOM 验证对象或规则章节；不得只写“小范围验证 / 局部验证 / 先看一处”。
- 当最小切片验证失败时，必须先诊断失败原因，不得继续扩大范围。

## 开工声明模板

执行态动手前必须声明：

```text
本轮准备修改的文件：
本轮禁止修改的文件或范围：
本轮已读取的规则文件：
当前生效入口：
本轮授权原文：
本轮复用的成熟页面：
本轮执行依据：
本轮是否允许新增交互、提示、测试项、验收项：
clone-source：
change-type：
```

不涉及页面、抽屉或复刻时，`clone-source` 与 `change-type` 可以标记为“不适用”，但不能省略判断。

## 执行依据

输出结论、字段、页面规则、接口参数、异常场景和改动建议时，只能引用以下依据：

- 用户本轮明确要求。
- 仓库现有代码、页面、设计稿。
- 需求文档、规则文档、接口文档。
- 用户确认过的成熟页面复用来源。

无依据时，只能写成 `待确认项`、`推断` 或 `现有文档未确认`，不得写成事实。

## 授权与上下文漂移硬闸门

文件修改授权只认本轮最新用户消息中的明确原文，不认以下内容：

- AI 自己上一轮写的计划、建议、开工声明或“接下来我会改”。
- 旧会话摘要、接力文档、上一位 AI 的最终回复。
- 用户上一轮或更早之前的执行授权，除非最新消息明确要求“继续按刚才方案执行”。
- 对话握手词“山”或“已读 Harness”。

以下情况必须重新读取当前本地规则入口，并重新判定状态。该闸门默认主要约束国内大模型或未知模型；Codex / GPT 场景不因常规多轮沟通自动触发，仅在用户强纠偏触发时强制执行：

- `AGENTS.md`、`harness/*`、工具规则或全局 Harness 刚被修改、回退、替换、删除或被审阅。
- 发生上下文压缩、跨线程接力、恢复旧对话、或用户说“你没按 Harness / 规则回退了 / 当前规则是什么”。
- 国内大模型或未知模型连续多轮讨论后准备第一次改文件。
- 用户最新消息出现“怎么优化 / 先讨论 / 你没懂 / 谁让你改 / grill me / 审阅 / 看看”等会改变状态的口径。

触发后，旧规则记忆和上一轮开工声明只作为线索，不得作为当前执行依据。当前回复必须写清“当前生效入口”和“本轮授权原文”；写不出授权原文时，结论只能是讨论、分析、审阅或排障，不能修改文件。

## 最终回复清单

执行完成后，最终回复至少说明：

- 本地改了哪些文件。
- 本轮没有改哪些高风险文件、页面、脚本或规则入口。
- 已运行哪些验证命令。
- 未运行哪些检查，以及原因。
- 是否已提交、commit hash、是否已推送、当前分支与远端同步状态。
- 涉及新增页面或入口时，说明源目录入口闭环状态与迭代引用策略；若未挂目录或未挂迭代，说明依据或待确认项。
- 本次新增问题。
- 仓库存量问题。
- 若线上依赖手动上传，列出必须上传的全部文件。
- 仍需用户确认的事项。

若本轮只生成报告，不改规则正文，必须明确“本轮仅新增审阅报告，未修改 `AGENTS.md` / Harness / standards 正文”。

上传清单必须按依赖枚举；不涉及项写“不涉及”，不得省略：

```text
页面 HTML：
入口 index：
迭代索引：
docs 数据源：
doc-panel / 公共组件：
CSS / JS 公共资源：
standards 登记：
```

## 禁止事项

- 不得把本文件当作新的主入口覆盖 `AGENTS.md`。
- 不得在讨论态修改文件。
- 不得无依据编造字段、接口、状态流转或异常场景。
- 不得把需求说明、开发备注、测试提示、版本摘要、模拟操作塞进真实页面正文、业务弹窗、业务抽屉或需求抽屉正文。
- 不得为“补充 / 优化 / 落文档”类需求做大范围重写。
- 不得因接入 `cc-sdd` 而复制一套与 `AGENTS.md` 平行的规则母本。
