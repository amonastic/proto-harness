# 任务契约

本文件承载页面、目录、新增页面、复刻改造等执行前契约，负责把抽象需求落到可核对的文件和页面差异。

## 页面调整契约闸门

页面调整契约用于把抽象需求、需求说明或方案翻译成可执行的逐页差异说明。用户是最高维度审阅者，不负责替 AI 拆字段、拆页面、拆布局或写具象调整计划；AI 必须主动完成这层翻译。

### 触发场景

出现以下任一情况，必须先输出页面调整契约：

- 一个需求涉及多个页面、多个端或同一页面的多个区域。
- 用户给的是业务目标、需求说明、方案判断、截图方向、口径修正或“看起来 OK”的抽象结论，但尚未逐页说明怎么改。
- 目标涉及字段、按钮、状态、默认值、空态、异常、文案、布局、层级、业务弹窗、需求抽屉、CSS 规范、入口闭环或 `design over` 收口。
- 指导者准备发包给其他执行模型，或当前 AI 准备自己直接修改文件。

### 契约必须包含

每个目标页面至少写清：

```text
当前依据：

```

### 契约分级（full / mini / 豁免）

- **full**：多页面、跨端、新增页面、结构调整、字段/状态/文案批量变化 → 使用上方完整 19 字段契约。
- **mini**：单页面、单区块、纯样式或局部控件调整 → 使用 6 字段精简契约：目标页面 / clone-source / 本轮改动点 / 验证方式 / 禁止范围 / 待确认项。
- **豁免**：同时满足「单文件 + 单组件 + ≤3 处纯样式属性 + 无结构/字段/交互/入口变化」的微调 → 免契约，但必须保留精简开工声明（4 项：目标文件 / 授权原文 / 禁止范围 / 验证方式）并执行页面与抽屉执行分卷中的视觉改动前强制三查。
- **同会话 delta 复用**：同一会话连续微调同一对象时，第 2 轮起可复用首轮契约基线，只声明本轮 delta（改了什么、验证什么）；基线或对象变化时重新出契约。
- 分级判断错误（把 full 任务当 mini 做）导致返工时，视为执行疏漏，须补 full 契约再继续。

### 执行边界

- “需求说明 OK / 方案 OK / 可以做”不等于可以直接改页面；只有页面调整契约也闭环，才允许进入文件修改。
- 页面调整契约适用于当前 AI 直接修改，也适用于把任务发给其他执行模型；不得因为没有单独执行者就跳过。
- 契约中无法从用户本轮要求、现有页面、需求文档、业务外脑、接口文档或成熟 `clone-source` 推导的关键项，必须标为 `待确认`，不得自行补成页面、字段、接口、权限或 `design over` 事实。
- 用户确认“页面独立 / 单独做 / 不接入既有能力 / 不再关联旧页面”只代表承载关系或数据关系独立，不等于允许 AI 自行扩展字段、枚举、接口对象或业务状态。字段必须逐项来自用户确认、既有页面、需求文档、接口文档或明确 `clone-source`；外部客户平台截图、执行者推断和上一轮错误文档只能作为线索，不能作为当前有效字段来源。
- 规则沉淀类任务若要新增 `修改历史`，必须先按 `DEVELOPMENT.md` 的“模块级修改历史规则”判断是否命中模块级稳定变化；未命中时不得自动新增历史菜单、历史卡片或历史条目。
- 命中模块级稳定变化时，同一批次多页面联动默认合并为一条修改历史记录；只有不同口径、不同发布批次或不同变更主题才拆分。
- 新增或调整 `修改历史` 后，必须反向检查：是否误计入业务入口或页面数量、是否被放入业务入口分组、是否污染迭代页 / 历史快照、是否需要进入上传清单；命中任一问题必须先修正再交付。
- 若契约存在高风险待确认项、越权删除、跨端口径未定、真实交互未授权或 `clone-source` 不明确，必须先交给用户审阅，不得直接修改。
- 若用户明确要求“直接做 / 按这个改”，AI 可以在开工声明中先生成契约并执行；前提是契约无高风险待确认项，且没有超出静态原型边界或禁止范围。

## 新增页面与目录引用契约

新增页面、复制页面、截图复刻成页面、让页面对开发可见、或把源页面挂入迭代时，必须先产出本契约；不涉及页面新增或入口调整时标为“不适用”。

```text
新增页面与目录引用契约：
页面落位：source-page / iteration-reference / snapshot / 不适用
源文件路径：
所属端与模块：
源目录入口：菜单项或模块卡片 / 页面承载区或 href / pageNames / 面包屑 / URL 参数
源目录分组与标签：
迭代引用策略：不挂迭代 / 挂当前迭代 / 待排期 / 冻结历史快照 / 待用户确认
目标迭代页：
是否涉及历史快照：
历史快照路径与依赖：
禁止事项：不得直接在迭代页新增源页面；不得让历史迭代引最新源页面；不得混放跨月目录标签
验证方式：
待确认项：
```

执行边界：

- `source-page` 默认落在对应端/模块源目录，`iteration-reference` 默认只引用源页面或快照，不承载真实页面开发。
- 新增源页面后，源目录入口未闭环时不得声称页面已可见；只登记 `standards/ui-spec.json` 或只放入迭代索引都不算源目录可见。
- 需要挂迭代但未能判断具体迭代时，必须询问用户；不得把页面默认塞进最新或历史迭代。
- 发现旧源目录中 `202605` 分组包含 `06上 / 202606上` 等串期条目时，必须先标为存量目录治理问题；普通页面需求不得顺手批量整理旧目录。
