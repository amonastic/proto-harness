# 页面名称 - 需求文档

> 交付策略：默认 `drawer-first`。普通迭代页优先补页面抽屉文档；仅当用户明确要求、需求属于大需求/跨多页方案或 0-1 模块时，再同步产出 `需求文档.md`。
>
> **Web 端 0-1 抽屉写法默认原则（重要）**
> 1. 不先堆“页面定位 / 角色与入口 / 测试注意事项 / 验收标准”这些套话。
> 2. 先把页面真正会影响设计、开发、联调的东西写清：**统计口径、筛选默认值、字段定义、操作显隐、状态关系、边界和待确认项**。
> 3. 能确认的写死；不能确认的不要偷补，直接放进 `待确认项`，一条一条问清楚。
> 4. 抽屉默认服务于“静态原型表达”，不要把“支持上传 / 支持删除 / 支持下一步”直接等价成必须把功能写出来。

## 适用判断

- 适用场景：Web 端后台业务页、列表页、详情页、台账页、订单页、单表单弹窗页
- 推荐结构：
  - **列表/台账页**：页面内容 → 交互规则 → 边界说明 → 待确认项
  - **详情页**：页面内容 → 交互规则 → 边界说明 → 待确认项
  - **复杂状态页**：核心流程 → 状态与分支 → 字段说明 → 交互规则 → 异常与边界 → 待确认项

## 页面内容

> 这一节不要写套话，要直接写页面由哪些真实业务区块组成。优先把“统计卡 / 筛选区 / 列表 / 操作列 / 弹窗入口 / 记录区”等结构讲清。

- 页面主结构：
- 顶部统计区（如有）：
- 筛选区（如有）：
- 列表 / 卡片区（如有）：
- 底部 / 工具栏动作（如有）：
- 相关弹窗 / 抽屉入口（如有）：

### 推荐写法（列表页）

| 区块 | 要写什么 |
|---|---|
| 顶部统计卡 | 指标名称、统计定义、是否跟随筛选结果联动 |
| 筛选区 | 字段名、控件形式、默认值、是否模糊搜索、是否单选下拉 |
| 列表字段 | 展示规则、空值规则、异常规则 |
| 操作列 | 什么状态出现什么按钮，什么状态隐藏 |
| 工具栏动作 | 是列表级动作还是单条动作；是否只是原型承接 |

### 推荐写法（详情页）

| 区块 | 要写什么 |
|---|---|
| 基础信息区 | 固定展示哪些字段 |
| 状态信息区 | 哪些字段可刷新，哪些字段只读 |
| 记录区 | 记录什么，不记录什么 |
| 主动作 | 有哪些动作，按现有框架展示即可，不要擅自写死具体技术实现位置 |

## 交互规则

> 这节要重点写“可执行规则”，不是泛泛地写“支持查看 / 支持操作”。

### 先写这几类
1. **筛选规则**
   - 默认值是什么
   - 查询后哪些区块联动刷新
   - 重置后恢复到什么状态
   - 输入框还是模糊搜索下拉
2. **状态规则**
   - 有哪些状态
   - 状态之间是什么关系
   - 是否存在双状态列（如支付状态 / 处理状态）
3. **操作显隐规则**
   - 哪些状态显示哪些按钮
   - 哪些状态禁止继续操作
4. **补查 / 刷新规则**
   - 刷新的是页面展示，还是补查业务结果
   - 哪些场景允许刷新，哪些不允许
5. **弹窗规则**
   - 标题是否随入口变化
   - 默认回填哪些字段
   - 提交成功后回写什么

### 推荐写法（显隐矩阵）

| 场景 | 可展示操作 | 说明 |
|---|---|---|
| 已绑定且正常 | 详情 / 续费 / 修改绑定 | 示例 |
| 待绑定 | 详情 / 绑定设备 | 示例 |
| 绑定异常 | 详情 / 修改绑定 | 示例 |

## 边界说明

> 这节默认只写真实会影响页面表达、设计验收、开发联调的边界，不写空话。

优先覆盖：
- 空值如何展示（`--`、空态、隐藏）
- 异常值如何展示
- 哪些组合当前不成立 / 待确认
- 接口失败后页面怎么处理
- 本地数据与供应商数据口径不一致时怎么判
- 原型只做静态表达、不做真实功能的边界

### 推荐写法（高频）
- 当前筛选结果为空时，顶部统计卡如何展示
- 某字段为空时是否仍允许查看详情
- 某状态是否允许继续操作
- 是否展示供应商原始单号 / 原始状态码

---

## 待确认项

> **只要你自己开始犹豫“这个是不是应该这样”时，就不要写进正式规则，直接丢到这里。**
>
> 推荐写法：一条问题 + 为什么需要确认，不要写成模糊句子。

### 必须进待确认项的内容
- 用户没明确确认、你只是根据经验推断出来的状态定义
- 供应商接口是否真的提供某个失败/取消/超时状态
- 某个统计口径是否按支付状态还是处理状态算
- 某个按钮是否真的要显示 / 隐藏
- 某个导出字段是否一定要有

### 推荐格式
- 待确认：`处理中` 是否仅按供应商真实充值处理中统计，还是包含我方已支付但未回调的订单？
- 待确认：销户卡是否允许继续提供修改绑定能力？
- 待确认：批量补录失败原因是否全部固化为正式规则？

## Web 端 0-1 页面专用检查清单

在你写完抽屉后，至少自查以下问题：

- [ ] 顶部统计卡是否写了**统计定义**，而不是只写名字
- [ ] 每个筛选项是否写了**控件形式 + 默认值**
- [ ] 列表字段是否写了**空值 / 异常值怎么展示**
- [ ] 操作列是否写了**什么状态出现什么按钮**
- [ ] 双状态列（如支付状态 / 充值状态）是否写清关系
- [ ] “刷新状态”是否写清到底是刷新展示还是补查结果
- [ ] 凡是没有明确确认的内容，是否都进了 `待确认项`
- [ ] 页面正文、业务弹窗、业务抽屉里没有混入开发提示/测试提示/说明性文案

## 不建议再默认保留的旧章节

以下章节除非用户明确要求，否则默认不写：
- 页面定位
- 角色与入口
- 测试注意事项
- 验收标准

如果确实要写，也应放在 **复杂模块总文档** 中，而不是抢占单页抽屉正文。
