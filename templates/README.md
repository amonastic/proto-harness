# 模板目录

本目录存放页面骨架与治理文档的可复制模板。它们**不会被任何脚本自动读取** —— 模板是给人和 AI 手工复制的基线，不是运行时依赖。

## ⚠️ 先读这一条：HTML 模板与脚手架是两套东西

`npm run scaffold:page` **不读本目录的 `.html` 模板**，它内部自带一份骨架字符串（见 `scripts/scaffold-page.js`）。

因此：

- 改了 `templates/模板-*.html`，**不会**改变 `scaffold:page` 的产出。
- 反过来，`scaffold:page` 的骨架也不会自动同步回这些模板。
- 两者可能漂移。改任一侧时，请同时核对另一侧，或明确以哪一侧为准（当前 `scripts/scaffold-page.js` 是机检和登记链路实际使用的那一侧）。

## 页面骨架模板（`.html`）

按 `DEVELOPMENT.md` 的页面类型四分法对应。选错类型是最常见的返工原因，判定规则见 `standards/page-type-guide.md`。

| 文件 | 页面类型 | 适用 | 明确禁止 |
| --- | --- | --- | --- |
| `模板-平台入口页（有导航）.html` | `platform-entry` | 平台（后台 / 客户端 / 小程序）的入口页，带侧边导航 | 用作模块业务详情页 |
| `模板-模块业务页（无导航）.html` | `module-page` | 具体业务页：列表、详情、配置 | 引入 `system-nav` 平台级导航 |
| `模板-迭代索引页（有导航仅聚合）.html` | `iteration-index` | 迭代索引页，只放功能入口索引 | 在本页直接做业务功能开发 |
| `平台标准页面模板.html` | `module-page`（完整版） | 需要左导航 `nav-item` / `nav-group-title` 结构的模块承载页参考实现 | — |

> `portal-index`（总导航 / 平台总览）目前只有 `scaffold:page` 内置骨架，本目录没有对应模板。

`平台标准页面模板.html` 与 `模板-模块业务页（无导航）.html` 的区别只在承载结构：前者给的是带左侧导航栏的完整模块页样式，后者是无平台导航的纯净业务页。实际写页面前，优先在同平台或同模块目录下找成熟页面复用（`DEVELOPMENT.md` 的「常见实现约束」），模板只是找不到成熟实现时的起点。

## 文档模板（`.md`）

| 文件 | 用途 | 被谁引用 |
| --- | --- | --- |
| `模板-需求文档抽屉.md` | 需求文档抽屉正文的结构起点 | 无（人工复制） |
| `模板-关键页面基线说明.md` | 关键页面的基线说明（页面目标、结构、边界） | 无（人工复制） |
| `执行者最终答复模板.md` | 执行者交付回执，把「执行者声称」逐项转成「本地已验证」 | `harness/04-规则准入与治理.md` |
| `规则任务包模板.md` | 把已裁决的规则治理目标打包交给执行者 | `harness/20-协作Prompt模板.md`、`harness/roles/指导审阅者.md`、`standards/rule-map.json` |

两个「无引用」的文档模板是纯人工复制件，不进入任何治理链路；改名或删除前确认没有会话在手工使用它们。

## 与机检的关系

页面骨架是否合规由 `npm run lint:ui` 按 `standards/ui-spec.json` 判定，模板本身不参与机检。新建页面后必须跑：

```bash
npm run check:ui          # 登记 + 结构机检 + 一致性审计
```

模板产出的页面仍需自行完成入口闭环（菜单项、承载区或 `href`、`pageNames` 映射），三者缺一视为入口未完成 —— 见 `DEVELOPMENT.md#目录入口注册闭环`。
